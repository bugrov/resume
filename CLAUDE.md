# CLAUDE.md

Инструкции для Claude Code при работе в этом репозитории.

## Что это за проект

Одностраничный сайт-визитка (резюме) Александра Бугрова, fullstack-разработчика.
Цель — произвести хорошее впечатление на рекрутера: стильный дизайн, плавная
навигация, тёмная/светлая тема, адаптивность под мобайл/планшет/десктоп,
поддержка трёх языков (RU/EN/JA).

## Стек и жёсткие ограничения

- **React 19 + TypeScript**, сборка **Vite**. Не переходить на Next.js — сайт
  статический, одностраничный, деплоится на Vercel как обычный Vite-проект.
- **Tailwind CSS v4** — конфиг CSS-first, живёт в `src/app/styles/tailwind.css`
  (`@import "tailwindcss"`, `@theme`, `@custom-variant dark`). Нет `tailwind.config.js`
  — это осознанно, так работает Tailwind v4.
- **SCSS** — только для того, что неудобно/невозможно чисто на утилитах Tailwind:
  кастомные keyframe-анимации, градиентный текст, эффект-пасхалка под курсором,
  CSS-переменные тем (`src/app/styles/_variables.scss`). Файлы: `_variables.scss`,
  `_animations.scss`, `main.scss` (агрегатор + сами кастомные классы).
- **Тёмная тема** — управляется классом `dark` на `<html>`, не media-query.
  Логика — `src/shared/lib/hooks/useTheme.ts`, ключ localStorage — `resume-theme`
  (см. `src/shared/config/constants.ts`). В `index.html` есть инлайн-скрипт,
  который выставляет класс `dark` ДО рендера React — если меняешь имя ключа,
  обязательно поменяй его и там, и в хуке.
- **Архитектура — Feature-Sliced Design**: `app → pages → widgets → features →
  entities → shared`. Импорты идут только "сверху вниз" (widgets могут
  импортировать shared/entities/features, но не наоборот). Алиасы путей заданы
  в `tsconfig.app.json` (`paths`) и продублированы в `vite.config.ts`
  (`resolve.alias`) — при добавлении нового алиаса меняй оба места.
- Иконки — **lucide-react** (обычные UI-иконки) и **react-icons/si** + `react-icons/hi`
  (бренд-иконки соцсетей и почта). Не тащить новые иконостеки без необходимости.
- Шрифты — самохостинг через `@fontsource-variable/*` (inter, space-grotesk,
  jetbrains-mono), импортируются в `src/main.tsx`. Не подключать Google Fonts
  через `<link>` — весь смысл в отсутствии внешних запросов.

## Мультиязычность (RU/EN/JA) и контент резюме — где менять

Сайт трёхъязычный: русский, английский, японский. Переключатель — иконка-флаг в
хедере (`src/features/locale-switch/LocaleSwitch.tsx`), переключение мгновенное,
без перезагрузки страницы (осознанное отклонение от исходной идеи "перегружать
страницу" — так плавнее и это ничем не хуже технически).

Весь текст сайта — **три больших словаря**, по одному на язык:
`src/shared/i18n/dictionaries/{ru,en,ja}.ts`, типизированы через
`src/shared/i18n/types.ts` (`Dictionary`). Здесь и UI-строки (нав, кнопки,
aria-label), и весь контент резюме (профиль, стек, преимущества, опыт работы,
навыки по группам, языки, образование, сертификаты) — сознательно держим всё в
одном словаре на язык, а не разносим "контент" и "UI-копирайт" по разным местам,
это было бы избыточно для одностраничника. Компоненты берут текст только через
`useLocale()` (`src/shared/i18n/useLocale.ts`) — `const { t } = useLocale()` — и
не хардкодят строки в JSX (кроме `социальных ссылок href/handle`, которые не
переводятся, см. `src/entities/social-links/model/data.ts`).

Технические идентификаторы (`id` у stack-item/advantage/experience/skill-group/
language/certificate, значения `icon`) должны быть **одинаковыми** во всех трёх
словарях — по ним идут React-ключи и маппинг на иконки (`shared/lib/iconMap.tsx`).
Переводится только то, что реально текст для человека.

Если меняется резюме на hh.ru — синхронизируй формулировки в `ru.ts` тоже, это тот
же человек и тот же стиль (fullstack, уклон в TypeScript-стек — Vue/Nuxt/React/Next
+ NestJS, PHP/1С-Битрикс как крепкий дополнительный навык, не основной), и заново
пройдись по `en.ts`/`ja.ts`, если менялся смысл, а не только формулировка.

Для японского — стиль вежливый, деловой (ですます調), это осознанный выбор для
резюме-сайта, а не разговорный/дружеский тон. Кастомные шрифты (`@fontsource-variable/*`)
покрывают только латиницу/кириллицу — для японского текста специально ничего не
подключали (это раздуло бы бандл), браузер сам подставляет системный CJK-шрифт
через стандартный font-fallback, выглядит нормально.

## Дизайн-система

- Палитра — фиолетово-сиреневая (`violet`/`fuchsia`/`sky` из палитры Tailwind),
  плюс нейтральные белый/чёрный/zinc. Не вводи новый основной цвет без запроса.
- Семантические CSS-переменные для поверхностей — `--bg`, `--bg-soft`, `--surface`,
  `--surface-border`, `--fg`, `--fg-muted`, `--accent`, `--accent-soft`, `--ring`
  (см. `_variables.scss`, значения для `:root` и `.dark`). Компоненты в основном
  берут их через `var(--fg-muted)` и т.п. или через Tailwind-классы `violet-600
  dark:violet-300` — оба подхода сосуществуют, это ок.
- Готовые переиспользуемые классы (см. `main.scss`): `.text-shine` (переливающийся
  градиентный текст для имени/акцентов), `.surface-card` (карточка с hover-lift),
  `.reveal`/`.reveal-visible` (scroll-reveal, управляется хуком `useInView` +
  компонентом `RevealOnScroll`), `.avatar-ring` (вращающееся кольцо вокруг фото),
  `.blob` (декоративные размытые пятна фона), `.cursor-reveal*` (пасхалка).
- Карусель стека (`StackCarousel`) — нативный горизонтальный скролл со
  scroll-snap, без сторонних библиотек каруселей. Не добавляй swiper/embla без
  явного запроса — цель была минимальный бандл.

## Пасхалка (footer spotlight)

`src/features/cursor-reveal/FooterSpotlight.tsx` + `SecretText.tsx` — по всему
футеру плавает размытая цветная "клякса" за курсором (`.footer-blob` в
`main.scss`, следует за курсором через `translate3d` в инлайн-style, не через
React state — иначе лишние ре-рендеры на каждый `pointermove`). Она рендерится
**позади** контента (copyright, соцсети — обёрнуты в `Container` с `relative z-10`),
поэтому ничего не перекрывает и не мешает кликам (у кляксы `pointer-events: none`).

Отдельно между copyright и иконками соцсетей сидит `SecretText` — маленький
приглушённый значок "✦", который при наведении кляксы раскрывается в градиентный
текст (`clip-path: circle()` по локальным координатам ЭТОГО элемента, а не
глобальным — это принципиально: `FooterSpotlight` на каждый `pointermove`
пересчитывает `--reveal-x/--reveal-y` отдельно для каждого элемента с атрибутом
`data-reveal-target` через его собственный `getBoundingClientRect()`, так что
эффект работает даже если таких раскрывающихся элементов на странице будет
несколько). На тач-устройствах — тап показывает и раскрывает клячксу на ~1.8с.

Текст пасхалки — `t.footer.secret` в словарях i18n (переведён на все три языка).

## Git / деплой — важно

- **У Claude есть постоянное разрешение коммитить и пушить в `main` в этом
  репозитории по ходу работы над сайтом**, без запроса подтверждения на каждый
  push (пользователь явно это разрешил при создании проекта). Это не
  распространяется на force-push, удаление веток/тегов и на другие репозитории.
- Реальный деплой делает **Vercel** — подключён напрямую к GitHub-репозиторию,
  подхватывает каждый push в `main` сам. Ничего руками деплоить не нужно и
  нельзя (нет доступа к аккаунту Vercel пользователя).
- `.github/workflows/ci.yml` — только проверка (`oxlint` + `tsc -b && vite build`)
  на push/PR, не деплой.

## Повторное разворачивание похожего проекта

Если понадобится собрать другой такой же сайт-визитку с нуля, порядок такой же,
как здесь: `npm create vite@latest . -- --template react-ts` → `@tailwindcss/vite`
(не postcss-плагин, в v4 он не нужен) → `sass` → `react-icons` + `lucide-react` →
`@fontsource-variable/*` → развести папки по FSD → алиасы в tsconfig+vite.config →
контент резюме — словарями в `shared/i18n/dictionaries/*.ts` (см. раздел про
мультиязычность выше), а не одним плоским файлом, если сайт должен быть
многоязычным с самого начала; для одноязычного сайта проще один файл в
`entities/resume/model/data.ts`.

Важный грабль, в который уже наступили: не вешай `overflow-x-hidden` на общий
корневой `<div>` страницы — в паре с `sticky` в хедере это ломает липкость
(overflow, отличный от `visible`, по спеке CSS превращает элемент в новый
scroll-container, и `position: sticky` внутри перестаёт работать относительно
вьюпорта). Если нужно защититься от горизонтального скролла — вешай
`overflow-hidden` точечно на секции с декоративными `.blob`, а не на весь layout.
